## G2 证据

- **调参集独立：** 1,024 个任务取自训练池，已断言与评测目标不相交。网格覆盖 k × lead，MPC 另加信赖域。
  - 选出的参数与论文一致：DLS k = 2，QP / MPC k = 1.5，lead 均为 0.15 rad。
- **配置冻结：**
  - 选定参数写在 `outputs/p1/tune/selection.json`。
  - 每次运行都有 manifest（`outputs/manifests/p1/`），记录配置、输入与输出的 hash，以及结果。
- **同预算、同接口：** 4,120 个相同任务；单次 160 步；30 Hz；同一 PD 与软限位。经典控制器按论文设定加精确重力前馈。
- **结果：** 单次 strict 的配对差（PolicyIK − 对照）如下，bootstrap 95 % CI 均远离 0：

  | 对照 | Δstrict | 95 % CI |
  |---|---|---|
  | DLS | +40.6 pp | [39.1, 42.1] |
  | QP | +35.6 pp | [34.1, 37.1] |
  | MPC | +35.0 pp | [33.5, 36.5] |

  - 经典控制器的数值与论文差 ≤ 2.5 pp。
  - 其 strict 失败中 75–84 % 是关节限位卡死（论文为 71–81 %）。
- **失败案例：** 逐任务 CSV 位于 `reports/p1/p1_per_task.csv`；分层结果（目标限位裕度、初始误差）见 P1 报告 §3。
- **已披露的差异：**
  1. PolicyIK + 重力前馈：论文 94.3 %，本地 0 %。原因是观测分布偏移，很可能需要另行训练的策略，仓库没有发布该 checkpoint。
  2. Isaac Lab 默认 DLS：论文 1.60 %，本地 55.3 %，原因未知。
  3. MPC 未实现硬件制动包络。

  三项均不影响主结论。

按计划的停止规则："若充分调优的传统 IK 与 PolicyIK 效果相当，则停止扩展。"本地结果显示两者差距约 35–41 pp，**不触发停止**。

## 对 P2 / G3（Franka）的建议：有条件 Go，先做低成本的前置验证

支持迁移的理由：
- 在同预算下，优势在统计上和工程上都显著；
- 经典控制器的主要失败模式（关节限位卡死）是结构性的，换成 Franka 也不会消失。

新增风险（超出论文范围，来自本地鲁棒性实验 P1 §7），需要写进 P2 设计：

1. **刚度失配敏感：** 已发布的 PolicyIK 只要 PD 刚度偏离 5 %，strict 就损失 14–25 pp；偏离 10 % 时损失 55–65 pp；coarse 基本不变。
   - Franka 训练必须加入 Kp/Kd、摩擦和负载随机化。
   - P2 的验收要把计划 E22（PD/负载扰动）从"可选"提升为"必做"。
2. **重力前馈与训练要一致：** 如果真机使用重力前馈，训练时也必须带前馈，否则 command-state 观测的分布不一致，策略会失效（本地 0 %）。
3. **参考跳变大：** PolicyIK 在早期的单步参考跳变 P99 为 1.43 rad，关节速度 P99 约 3.1 rad/s。
   - Franka 的速度、加速度和 jerk 限值更严格，需要在动作层加限速，或者把速率惩罚写进奖励，并作为安全指标验收。
4. **训练成本：** 论文的训练量约为 1.28×10⁹ 次交互。P2 意味着重新训练 PPO，需要负责人批准算力，并且要和本机上其他 GPU 任务（例如 rsi_rl）协调排期。

建议的 P2 第一步（不需要训练，只需约 1–2 天工程量）：
- 引入 Franka 资产，做 20 个构型的 FK 一致性核验；
- 在 Franka 上跑通 DLS/QP 基线；
- 冻结 Franka 的训练/测试集（测试集 ≥ 170 个目标，并按最小可检测差异估算样本量）。

完成以上步骤后，再由负责人决定是否投入 PPO 训练。

**本次没有启动 P2，也没有进行任何 PPO 训练。**
